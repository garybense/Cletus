## 2026-09-08 - Batching Inter-Agent Inbox Updates & Automated Child Process Reaping / **Learning:** Individual SQLite UPDATE transactions per inbox message during inter-agent message processing introduced high write latency per heartbeat turn. Additionally, un-reaped dead/failed child processes accumulated without automated cleanup. / **Action:** Batched inbox status updates into single transaction passes in ColonyMessaging.processInbox and implemented automated child process/sandbox reaping via ChildMonitor.reapStaleChildren.

## 2026-09-09 - Dual Scheduler Compatibility & Active Goal Filtering / **Learning:** DurableScheduler constructor signature mismatch broke heartbeat test execution when called with legacy parameters. Additionally, getReadyTasks queried pending tasks across all goals without filtering by active goals, allowing stale/failed goals to block scheduling. / **Action:** Refactored DurableScheduler to support both worker-id and legacy DB/task-map constructor signatures, executing both Phase 1.1 heartbeat schedules and Phase 1 queue work. Updated getReadyTasks to join the goals table and filter by active goals.

## 2026-09-09 - Child Monitor Message Table Query Alignment / **Learning:** ChildMonitor previously queried a non-existent "messages" table with "sender" and "recipient" columns when resolving last message timestamps during child health surveillance, which caused SQLite runtime errors when evaluating child agent activity. / **Action:** Updated ChildMonitor.checkChild to query the "inbox_messages" table using "from_address" and "to_address" with "received_at" timestamps.

## 2026-09-09 - Circuit Breaker Cooldown Reset & Solana Wallet Priority / **Learning:** ResilientHttpClient previously failed to reset `consecutiveFailures` when `circuitOpenUntil` expired, causing any subsequent failure to re-trigger the circuit breaker immediately. Additionally, config chain type overrides could misidentify a Solana wallet as EVM during startup registration. / **Action:** Updated `isCircuitOpen()` in `src/mindmods/http-client.ts` to reset `consecutiveFailures` and `circuitOpenUntil` upon cooldown expiration, and updated `resolvedChainType` in `src/index.ts` to prioritize `walletChainType` over `config.chainType`.

## 2026-09-09 - Preservation of Compute Credits & OpenClaw Direct Execution / **Learning:** Overwriting compute credits with $0.00 wallet USDC killed Cletus operational capability under empty wallet state. Additionally, OpenClaw child messaging lacked direct turn execution over SSH/local CLI. / **Action:** Preserved API compute credits in `getFinancialState` and `buildTickContext` when wallet USDC is 0. Implemented direct `runOpenClawChildTurn` in `message_child`, added address format validation in `send_message`, and added automated OpenClaw recovery in `ChildMonitor`.

## 2026-09-09 - Automated Heartbeat Child Process Reaping / **Learning:** Stale/stopped child processes remained in SQLite `children` table without automated cleanup during heartbeat tasks, consuming child pool slots. / **Action:** Updated `registerBuiltinHeartbeatTasks` to accept database reference and query/reap stale `failed` and `stopped` child processes older than 1 hour into `cleaned_up` during periodic `CLEANUP` heartbeat tasks.

## 2026-09-11 - Single-Pass Child Surveillance, Work Queue Batching & Durable Punishment History / **Learning:** Executing individual SQL queries per child during health checks and issuing remote SSH calls on inactive OpenClaw processes introduced unnecessary turns and latency in colony surveillance. Additionally, single-item work queue claims restricted task throughput under high load, and transient punishment maps lost discipline records across tool calls. / **Action:** Consolidated child monitor task metrics into single-pass SQL statements, skipped remote SSH checks on stopped/failed children, implemented `claimBatch` in `work-queue/queue.ts` for atomic multi-item claims, and persisted punishment history to the KV store.
